Phase 4 — Session and calendar layer

FX week boundaries, DST handling, rollover windows, and per-currency holiday calendars. Underrated, disproportionately interview-relevant, and — as Phase 0 discovered — a partial dependency of Phase 1 rather than a later add-on.

Exit criterion: for any timestamp, answer which session it falls in, whether it is rollover, and whether it is a holiday for either leg of the pair. planned
Why this phase moved earlier. Dukascopy returns HTTP 200 with a 0-byte body for closed sessions, not a 404. HTTP status therefore cannot distinguish "market closed" from "feed gap" — only the session calendar can. Phase 1's coverage report needs this.

What the session table must answer

{{ m.card_open('Joinable to any timestamp', 'recorded', '') }}
Which session? Sydney, Tokyo, London, New York — and the overlaps, which are where liquidity concentrates.
Is it rollover? The window moves with DST, so it cannot be a fixed UTC constant.
Is it a holiday for either leg? EURUSD on US Independence Day is a different instrument from EURUSD on a normal Thursday. Both legs matter, not just the quote currency.
Is the market open at all? Sunday open and Friday close move with DST. This is the answer Phase 1 needs to tell an empty payload from a missing one.
