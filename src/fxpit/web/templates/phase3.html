Honest timestamps

{{ m.card_open('Every observation carries a precision', 'recorded', 'planning.md: "Where the exact time is unknown, record it explicitly as unknown rather than assuming."') }}

RTDSM publishes a vintage month. ALFRED publishes a vintage date. Neither publishes a release time. Only the agency schedules give 08:30 ET, and only for the releases they cover — so 100% of the loaded archive carries month precision, and says so.

Coarse timestamps are placed at the LATEST instant consistent with what is known — a month-precision vintage sits at the last moment of its month. That biases every query toward withholding rather than leaking. A value whose release time is unknown is treated as not-yet-public for longer than it may truly have been, never for less.

The direction of the error is the whole point. Under-reporting what was knowable is a conservative research error that costs you signal. Over-reporting it is look-ahead bias, which is the failure this database exists to prevent. Assuming 08:30 ET everywhere would manufacture precision that was never measured — the same error as using a revised value, wearing different clothes.

The first version of this ranking reported that 1985Q3 real GNP was revised from 1,684.8 to 8,604.2 — a 6,919-point revision. It is not a revision at all. Real GDP is published in chained dollars of a base year, the base year moved from 1982 to 2017, and a rebasing shifts every historical period at once. That is a units change, not new information.

Narrowing the comparison window did not fix it: at 400 days the same period still showed 113%, because base-year changes fall inside a year of the first print. Nor did a single-vintage step. There is no window tight enough, so the series are excluded rather than quietly included, and comparing them properly needs rebasing detection that is not implemented.

Recorded prominently because it is the project's own failure mode turning up in its own output: a plausible-looking number, no error, nothing to alert you. The only defence was knowing what the units meant.

The read contract

{{ m.card_open('as_of(t) is the only sanctioned read path', 'recorded', '') }}

Filters known_at <= t and keeps the row with the greatest known_at per (series, ref_period). Returns an empty result when nothing was known yet — never a later vintage, never a placeholder, never a zero.

The value of that guarantee comes entirely from there being exactly one implementation of the filter. Postgres-backed macro reads and ClickHouse-backed tick reads therefore materialise into DuckDB relations with fixed shapes, and every as_of function is SQL over those relations. Where the rows came from changes the loader, never the filter.

A NULL value is a real fact, not an absence: a release published as missing has a known_at and must not be skipped in favour of the next numeric vintage. Passing a bare date raises rather than coercing to midnight — the cheapest check in the codebase, guarding the most expensive mistake.
