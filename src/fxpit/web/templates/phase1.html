Phase 1 — Tick ingest

Fetch and decode Dukascopy .bi5 hourly files into tick_raw. Resumable, idempotent, rate-limited, and never transformed on ingest. Start narrow — 7 majors from 2015 — and extend backward only once the pipeline is boring.

Exit criterion: re-running the ingest produces zero new rows and zero errors. next up
The decoder is already proven. The Phase 0 source check decoded 4,508 real EURUSD ticks, confirmed the zero-based month indices empirically, and confirmed the per-instrument decimal factor (1e5 for EUR pairs, 1e3 for JPY). The riskiest part of this phase was de-risked before it started.

Ingest gotchas

{{ m.card_open('Each produces plausible-looking wrong data, not an error', 'recorded', 'Recorded because a loud failure is cheap and a quiet one is not.') }}
Zero-based month indices Confirmed by measurement: month 00 returns January (mean bid 1.09409), month 01 February (1.07665). An off-by-one silently returns a different month's prices.
Per-instrument decimal factor JPY pairs use 1e3, EUR pairs 1e5. Wrong factor gives prices off by two orders of magnitude — obvious — or subtly wrong, which is worse.
Weekends return HTTP 200 with 0 bytes Corrected by measurement. planning.md originally said weekends were absent. They are not — Dukascopy serves an empty file, so HTTP status cannot distinguish closed-market from feed-gap. The ledger must consult the session calendar, which makes Phase 4 a partial dependency of this phase's coverage report.
Legitimately empty hours Thin holiday sessions return valid empty payloads. Not an error, and must not be retried forever.
