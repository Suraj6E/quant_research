Ingest gotchas

{{ m.card_open('Each produces plausible-looking wrong data, not an error', 'recorded', 'Recorded because a loud failure is cheap and a quiet one is not. All four were confirmed by measurement rather than read from documentation.') }}
Zero-based month indices Month 00 returns January (mean EURUSD bid 1.09409 on day 09), month 01 February (1.07665). An off-by-one silently returns a different month's prices.
Per-instrument decimal factor JPY pairs use 1e3, others 1e5. The same integers decode to 143.946 or 0.143946 depending on which is applied. Unknown instruments raise rather than defaulting.
Ask precedes bid on the wire The 20-byte record is (ms, ask, bid, ask_vol, bid_vol). Swapping them yields a uniformly negative spread, which reads as a broken feed rather than a decode bug — so the failure gets blamed on the wrong thing.
Weekends return HTTP 200 with 0 bytes Corrected by measurement. planning.md originally said weekends were absent. They are not — an empty file is served, so HTTP status cannot separate closed-market from feed-gap. This makes Phase 4 a partial dependency of this phase's coverage report.
Concurrency draws throttling Found during the first live run. Four workers at a 0.15s pause earned a burst of HTTP 503s and 10 failed hours. Defaults are now 2 workers at 0.25s, with jittered backoff on 429/503 so retrying workers do not resynchronise and recreate the burst.

How idempotency works

{{ m.card_open('claim → insert → settle', 'recorded', 'The ordering is the whole mechanism, and reversing it would be much worse than leaving it out.') }}

An hour is written in three steps: a ledger row is claimed as in_progress, ticks are inserted as a single block, then the row is settled as ok. A crash between steps 2 and 3 leaves a claim whose rows may or may not exist — so on startup every in_progress row is treated as suspect, its ticks are deleted, and the hour is re-fetched cleanly.

Settling before inserting would be the tempting simplification and the dangerous one: a crash would mark an hour permanently complete with no data in it, and the ledger would confidently report coverage that does not exist.

Idempotency comes from never re-fetching a settled hour, not from de-duplicating afterwards. Dedup would need either a mutable tick table — forbidden — or a scan across billions of rows.
